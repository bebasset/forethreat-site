02Coverage

What we test

Built on the OWASP Web Security Testing Guide (WSTG), with most of the effort spent where real breaches happen: deciding who is allowed to do what.

Authorization & business logic (the core)

  • Horizontal and vertical privilege escalation across every role you give us
  • Tenant isolation: can Company A read or change Company B's data?
  • IDOR/BOLA on object identifiers, exports, and file downloads
  • Workflow abuse: skipping steps, replaying actions, race conditions, price/quantity tampering
  • Mass assignment on profile, role, and plan fields

Authentication & sessions

  • Login, MFA, SSO/SAML/OAuth, and session handling
  • Password reset and email-change flows
  • Account enumeration, brute-force and credential-stuffing controls
  • JWT and token handling, logout and session expiry

Injection & server-side

  • SQL/NoSQL injection, server-side template injection, command injection
  • SSRF, including access to cloud metadata endpoints
  • File upload, path traversal, XXE, insecure deserialization
  • Web cache poisoning and request-smuggling indicators

Client-side & configuration

  • Stored, reflected, and DOM XSS, including CSP bypasses
  • CSRF, CORS misconfiguration, clickjacking, open redirects
  • Sensitive data exposure in responses, JS bundles, and errors
  • Security headers and TLS, reported only where they matter

  • Number of user roles and tenants to test between
  • Number of features, workflows, and integrations
  • Authentication complexity (SSO, MFA, multiple identity providers)
  • Testing environment (staging vs. production windows)

What we need from you

  • Two test accounts per role (or permission to create them)
  • The URL(s) in scope and any areas that are off-limits
  • A technical contact during testing hours
  • Signed agreement, rules of engagement, and authorization to test
