External network test

For: any organization with internet-facing systems

Often requested by cyber-insurance applications, customer reviews, and regulations such as PCI DSS (requirement 11.4) and the FTC Safeguards Rule for covered financial businesses.

  • Discovery of exposed hosts, services, and forgotten assets in scope
  • VPN, remote access (RDP/SSH), firewall and email gateway exposure
  • Default credentials, known-vulnerable software, weak TLS
  • Manual validation and exploitation of what's actually reachable
  • Login portals tested for password spraying (within agreed limits)
Internal / Active Directory test

For: organizations running Windows domains and on-prem or hybrid networks

Usually run as an assumed-breach test: we start with a standard user account and a foothold on your network, the same position as a phished employee.

  • AD enumeration and attack-path mapping (BloodHound)
  • Kerberoasting, AS-REP roasting, delegation and ACL abuse
  • AD Certificate Services (ADCS) misconfigurations
  • NTLM relay, credential exposure, local admin reuse, lateral movement
  • Network segmentation checks between the zones you specify

Engagement prerequisites

  • Signed agreement, rules of engagement, and written authorization from the network owner
  • For MSP-managed networks: authorization from the end client as well as the MSP
  • Written approval from cloud/hosting providers where their terms require it
  • Internal tests: a VM or VPN access, plus a standard domain user account
  • Agreed testing windows and an emergency contact

What we don't do by default

  • Denial-of-service or load testing
  • Phishing or physical intrusion
  • Changes to production systems without explicit approval
  • Testing systems you can't authorize (e.g., your SaaS vendors)
